eBootloader — Multi-Architecture Bootloader

eBootloader is the boot stage of the EoS stack — a portable, signed, A/B-slotted bootloader that already supports 24 reference boards across 10 instruction-set architectures and degrades gracefully under power loss or corrupt updates.

Overview

What eBootloader is

eBootloader handles everything between reset and kernel hand-off: chain-of-trust verification, A/B slot selection, recovery fallback, network boot, and device-tree fixup. It speaks the same configuration model on every supported architecture, so porting a board takes hours, not weeks.

Robustness is the point: any failed update rolls back automatically; any corrupt slot triggers recovery; any tampering breaks the signature and refuses to boot.

Features

The shape of eBootloader at a glance.

▣

10 Architectures

ARMv7-M, ARMv8-A, RISC-V (RV32, RV64), x86_64, AArch64, MIPS, PowerPC, Xtensa, AVR.

▣

24 Reference Boards

STM32, NXP i.MX, Raspberry Pi, BeagleBone, ESP32, RISC-V SiFive, NVIDIA Jetson, and more.

▣

A/B Update Slots

Two firmware slots with automatic fallback if a new image fails to mark itself healthy.

▣

Signed Images

Ed25519 / ECDSA signature verification rooted in immutable boot ROM.

▣

Encrypted Updates

Optional AES-GCM payload encryption for over-the-air delivery.

▣

Recovery Mode

Standalone recovery slot with USB / UART / TFTP firmware upload.

▣

Fast Boot

Sub-second cold boot on Cortex-M, sub-3-second on Cortex-A SoCs.

▣

Device-Tree Patcher

Run-time DTB overlays for board variants without re-flashing the bootloader.

▣

Watchdog Hand-Off

Hard watchdog armed before kernel runs; rolls back if kernel doesn't check in.

Architecture

eBootloader Secure Boot Chain

The five-stage chain of trust from immutable ROM through BL1, BL2, verified firmware, and application, with ECDSA-256 signature verification and anti-rollback counters at each stage.

Technical Specifications

eBootloader at a Glance

Signature AlgorithmECDSA-256 (NIST P-256 curve)
Hash FunctionSHA-256
EncryptionAES-256-GCM for encrypted firmware images
Anti-RollbackMonotonic counter in OTP / eFuse; configurable policy
Supported ArchitecturesARM Cortex-M/A/R, RISC-V RV32/RV64, x86 (UEFI), MIPS, ARC, Xtensa, MIPS, ARC
Footprint< 32 KB flash (BL1 + BL2 combined)
Boot Time< 50 ms from power-on to kernel handoff on Cortex-M4 @ 168 MHz
Hardware Trust AnchorsTPM 2.0, ARM TrustZone, RISC-V PMP, eFuse / OTP
Firmware UpdateOTA-ready; dual-bank A/B update with atomic swap
Debug InterfaceJTAG/SWD lock-out in production mode; debug unlock via signed token

Quick Start

Signing a Firmware Image

ShellQuick Start
# 1. Generate a signing key pair (one-time setup)
ebuild keygen --algo ecdsa256 --out keys/signing_key

# 2. Build the firmware
ebuild build --profile cortex-m4-generic --out build/firmware.elf

# 3. Sign the firmware image
eboot sign \
  --input  build/firmware.elf \
  --key    keys/signing_key.pem \
  --output build/firmware.signed.bin \
  --version 3                      # anti-rollback version

# 4. Verify the signature locally
eboot verify \
  --input  build/firmware.signed.bin \
  --pubkey keys/signing_key_pub.pem

# 5. Flash to target
ebuild flash --image build/firmware.signed.bin --profile cortex-m4-generic

The bootloader public key is provisioned into OTP/eFuse at manufacturing time.

Applications

Where eBootloader Is Used

🔒

Secure Firmware Updates

OTA firmware updates with cryptographic verification prevent malicious firmware injection across the entire device fleet.

🏭

Manufacturing Provisioning

Automated key injection and certificate provisioning at the factory floor using eBootloader's signing toolchain.

🚗

Automotive Secure Boot

Meets ISO 21434 cybersecurity requirements for ECU firmware integrity in connected vehicles.

🏥

Medical Device Security

FDA pre-market cybersecurity guidance compliance through verified boot and anti-rollback protection.

Satellite Payloads

Industrial IoT

Prevents unauthorized firmware on field devices; supports remote attestation for IEC 62443 compliance.
