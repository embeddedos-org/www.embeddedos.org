eDB — Embedded Database

eDB is the EoS embedded database — a single, embeddable engine that speaks SQL, document, and key-value, exposes a REST API, ships JWT auth, and encrypts data at rest with AES-256.

Overview

What eDB is

Where embedded apps usually pick between SQLite (relational), a JSON file (document), and a config blob (KV), eDB gives you all three in one process — pick the right model per collection without spinning up another database.

REST and capability-gated EIPC access make it equally usable from a local app, a remote service, or a federation of devices.

Features

The shape of eDB at a glance.

▣

Three Data Models

SQL tables, JSON documents, key-value buckets — same transaction surface.

▣

REST API

Auto-generated CRUD endpoints with OpenAPI schemas.

▣

JWT Auth

Pluggable identity providers; per-collection ACLs.

▣

AES-256 At Rest

File-level encryption; keys rooted in the eBoot chain-of-trust.

▣

Replication

Multi-master CRDT-based sync across nodes; conflict-free by construction.

▣

Time-Travel Queries

Query past snapshots; built-in audit log per collection.

▣

EIPC Binding

Native capability-gated access from any EoS process.

▣

Backup & Restore

Point-in-time snapshot, encrypted offsite backup.

▣

Embeddable

< 2 MB binary; runs in-process or as a shared service.

Architecture

eDB Embedded Database Architecture

The eight-layer eDB architecture from SQL query interface through query planner, transaction manager, B-Tree index, page cache, storage engine, AES-XTS encryption, down to the physical storage media.

Technical Specifications

eDB at a Glance

Query LanguageSubset SQL (SELECT, INSERT, UPDATE, DELETE, CREATE TABLE, INDEX) + JSON Path
Transaction ModelACID transactions with Write-Ahead Logging (WAL) and MVCC
Index TypesB-Tree (range queries), Hash (equality), Full-text (trigram)
EncryptionAES-256-XTS per-page encryption; key derivation via HKDF-SHA256
Minimum RAM64 KB (page cache + B-Tree nodes for a 4-table schema)
Storage BackendsNOR Flash, NAND Flash, SD/eMMC, QSPI Flash, SRAM/PSRAM, POSIX file system
Max Database SizeUp to 4 GB on 32-bit targets; unlimited on 64-bit
Concurrent ReadersUnlimited concurrent reads (MVCC snapshot isolation)
Write ThroughputUp to 50,000 inserts/second on Cortex-M7 @ 480 MHz with NOR Flash
Crash RecoveryAutomatic WAL replay on power-loss recovery; < 100 ms recovery time

Quick Start

Storing Sensor Data with eDB

CQuick Start
#include "edb/edb.h"

/* Open (or create) an encrypted database */
static edb_t *db;

void db_init(void) {
    edb_config_t cfg = {
        .backend    = EDB_BACKEND_NOR_FLASH,
        .flash_base = 0x08080000,
        .flash_size = 512 * 1024,   /* 512 KB */
        .page_size  = 4096,
        .encrypt    = true,
        .key        = device_secret_key,  /* 32-byte AES key */
    };
    db = edb_open(&cfg);

    /* Create table if it doesn't exist */
    edb_exec(db,
        "CREATE TABLE IF NOT EXISTS readings ("
        "  id        INTEGER PRIMARY KEY AUTOINCREMENT,"
        "  ts        INTEGER NOT NULL,"
        "  sensor_id INTEGER NOT NULL,"
        "  value     REAL    NOT NULL"
        ");");
}

void db_insert_reading(uint32_t ts, uint8_t sensor_id, float value) {
    edb_stmt_t *stmt = edb_prepare(db,
        "INSERT INTO readings (ts, sensor_id, value) VALUES (?, ?, ?);");
    edb_bind_int(stmt, 1, ts);
    edb_bind_int(stmt, 2, sensor_id);
    edb_bind_real(stmt, 3, value);
    edb_step(stmt);
    edb_finalize(stmt);
}

eDB uses WAL mode by default — no data loss on power failure.

Applications

Where eDB Is Used

📊

Sensor Data Logging

Time-series sensor data storage on microcontrollers with automatic wear leveling and crash-safe writes to NOR Flash.

🏥

Medical Records

Encrypted patient data storage on implantable and wearable medical devices with ACID guarantees and tamper evidence.

🚗

Automotive Event Logging

Black-box event logging for ADAS and autonomous vehicles with millisecond-precision timestamps and crash recovery.

🏭

Industrial Historians

Process historian functionality on edge PLCs and RTUs, storing production data locally before cloud synchronization.

🔒

Secure Configuration

Encrypted device configuration and provisioning data storage with integrity verification on IoT devices.

🌐

Offline-First IoT

Local data buffering on IoT devices during connectivity outages, with automatic sync when connection is restored.
