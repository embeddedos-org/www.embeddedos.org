SECURE IPC

EIPC Embedded Secure IPC

The communication backbone — transport, security, and trust for the entire ecosystem

HMAC-SHA256 Integrity

Every frame is signed with HMAC-SHA256 using a built-in zero-dependency SHA-256 implementation. No OpenSSL or external crypto libraries required.

Capability-Based Auth

Each message carries a capability tag (e.g., ui:control). Server checks against action allowlists. Service identity + session tokens + capability validation.

Audit & Health

JSON-line audit trail for every controlled action. Heartbeat-based liveness monitoring with configurable intervals. Priority lanes P0-P3 for real-time traffic.

EIPC Wire Protocol

1

Preamble (16 bytes)

Magic bytes [0x45,0x49,0x50,0x43] + protocol version (v1) + message type (intent/ack/heartbeat/tool) + flags (HMAC enabled)

2

Header (JSON, max 1024 bytes)

service_id, session_id, request_id, sequence number, timestamp (RFC3339), priority (P0-P3), capability tag, payload_format

3

Payload (JSON, max 8192 bytes)

Intent data, tool request parameters, ack response, or heartbeat — type-specific structured JSON

4

HMAC-SHA256 (32 bytes)

Signature over preamble + header + payload. Verified on receive. 128-entry sliding window for replay protection.

Go 1.22 (Core)

Server, router, authenticator, capability checker, service registry, audit logger, health monitor — all using Go stdlib only

C11 SDK

Wire-compatible client/server library for C applications. Ships built-in SHA-256 — zero external dependencies. Enables ENI ↔ EAI communication.
