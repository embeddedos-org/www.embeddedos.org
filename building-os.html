Building an OS from Scratch

A deep dive into how EmbeddedOS was designed and built — the architecture decisions, tradeoffs, and lessons learned.

1. Why Build a New OS?

Existing RTOS options (FreeRTOS, Zephyr, RIOT) are excellent but fragmented. EmbeddedOS was designed to be a coherent, vertically integrated stack: one kernel, one IPC layer, one AI runtime, one build system — all designed to work together from day one.

The goal: a developer should be able to go from a bare STM32 board to a running AI inference application in under 10 minutes, with no dependency hell.

2. Kernel Architecture

EoS uses a microkernel-inspired design: the kernel handles scheduling, memory protection, and IPC. Everything else (drivers, filesystems, network stacks) runs in user-space processes communicating via eIPC.

The scheduler is a tickless, priority-based preemptive scheduler with sub-microsecond context-switch latency. The context-switch path is the target for formal verification in 2026.

EoS Kernel Documentation →

3. Secure Boot Chain

eBoot implements a 3-stage boot chain: immutable ROM stage-0 → signed stage-1 → verified application. Ed25519 (RFC 8032) signatures protect every stage. A/B partitions enable atomic over-the-air updates with automatic rollback on failure.

eBoot Documentation →

4. Inter-Process Communication

eIPC provides zero-copy message passing between processes using shared memory regions with hardware MPU protection. The API is inspired by POSIX message queues but designed for deterministic real-time behavior with bounded latency.

eIPC Documentation →

5. The Build System

ebuild is a CMake-based build system with a declarative board description format. Adding support for a new board requires only a YAML file describing the chip family, flash/RAM layout, and peripheral map. ebuild generates the linker script, startup code, and BSP automatically.
